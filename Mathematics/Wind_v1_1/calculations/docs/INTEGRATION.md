# Подключение двух независимых архивов к Ebala

1. Разместить рядом две **распакованные** папки `SP20_AppendixV_Wind_Reference_v0_6` и `SP20_Wind_Calculation_DB_v0_5` либо разрешить указать путь каждой папки самостоятельно.
2. Проверять `MANIFEST.json` и контрольные суммы обоих источников при подключении; ошибку отсутствующего внешнего справочника выводить до расчёта, не заменять коэффициенты на ноль.
3. При выборе расчётной схемы искать `cases[].case_id`, затем поля `inputs_by_case.csv`, формулы `formulas.json` и нормативные значения из **своих** таблиц 11.1–11.8 и **внешних** В.1–В.12/В.5–В.23.
4. Будущий вычислитель должен быть универсальным: разрешённые арифметические операции, табличная выборка, линейная/логарифмическая интерполяция, интервальные условия, ветви и явные альтернативные варианты. Не исполнять произвольные строки выражений через eval.
5. При отклонении от условий применимости предупредить в интерфейсе. Математически возможное значение не блокировать только из-за нормы; действительно неопределённую формулу не вычислять. Не выдумывать значения отсутствующих коэффициентов.
6. Для DOCX передавать **результат ядра** плюс фактически принятые коэффициенты/формулы. Для XLSX передавать **исходные значения**, вычислять коэффициенты и нагрузки независимыми формулами Excel с листами нормативных таблиц. Эти правила утверждены в PROJECT.md.
7. Сохранённый блок должен хранить снимок входов, выбранного режима графика (В.16, В.17), идентификаторы формул и исходные данные, чтобы обновление справочника не меняло старый расчёт без явного пересчёта.

**Ни один файл программы Ebala настоящим пакетом не изменён.**

## Экспериментальная проверка чтения формул

`tools/demo_arithmetic_reader.py` демонстрирует вычисление **простых скалярных** формул непосредственно из `data/formulas.json` через безопасный список математических операций (без eval). Автоматические тесты используют эту процедуру. Она не означает, что расчётная модель, выбор схем, таблиц, динамика или интерфейс Ebala реализованы.

## Особые зависимости приложения М (исправлено в v0.2)

- (М.11) `Delta2_k` зависит от `gamma_k` в первой степени; выражение хранится в `data/formulas.json`.
- (М.18) обязательным аргументом является `v0_squared`, рассчитанный по (М.20), а не `V0`. Не подставлять скорость на высоте 10 м вместо результата интеграла.
- М.19 при `k=k₁=s` даёт `xi_s_squared`, после чего проверяется критерий М.18. Приложение М нельзя исполнять без численного интегратора и форм колебаний.

### Коэффициент динамичности ξ, рисунок 11.1

При выборе схемы с (11.7) сначала вычислить `Tg1` по (11.8), взять суммарный декремент `delta_damp`, затем вызвать формулу `11.1.xi_davenport_approx` из `formulas.json`. Не считывать и не интерполировать координаты `graph_11_1_dynamic_coefficient.json`, они предназначены только для контроля. Применять принятую приближённую формулу одновременно в ядре и независимой формуле XLSX; передавать в DOCX рассчитанное ядром ξ. Показать в интерфейсе сообщение о статусе инженерной аппроксимации и проверенной области, не включать служебные предупреждения в клиентский отчёт.

**Отдельно:** (11.9а) требует `Tg_lim` из таблицы 11.5. Непрерывное вычисление ξ **не** создаёт нормативную формулу для интерполяции `Tg_lim` по δ.


## Идентификаторы обозначения f после замечаний к v0.3

Ссылаться на поля базы только по машиночитаемому ID:
`f_rise` (м, геометрия В.5/В.6) и `f_spectral` (Гц, приложение М).
На схемах и в нормативных печатных формулах оба показаны как `f`; связывать обозначение с машинным ID через `drawing_symbol_bindings` (для случаев) и `source_symbol_bindings` (для формул). Не использовать неоднозначный ключ `f` в JSON проекта или аргументах интерпретатора. При переходе с v0.3 не смешивать старые и новые пакеты расчётной базы.

`v0_squared` имеет unit `1` и поступает исключительно из вычисления (М.20); ошибка размерности может быть обнаружена проверкой `S_v0 [с] × r_m [1] × df [Гц] -> 1`.


## Специальные справочники СП375

- Для `SP375_TOWER_ZONAL_WIND` найти в справочнике `external/sp375_appendix_a_zonal_factor.json` по `dataset_id=SP375_A2_ZONE_X`, вычислить x по прямым участкам [0,10],[10,30],[30,50] и затем умножить локальную нагрузку `w_loc=x*w`. Выпустить два **альтернативных** загружения (снижение выше / ниже перелома).
- Для `SP375_CHIMNEY_SPECIAL_WIND` выбирать γf по `data/special_sp375_rules.json`, особый приоритет для стальных труб и башен; при H>210 м требовать явное значение из задания.
- Не объявлять выполненным расчет вихревого возбуждения или усталости.
- Показывать **МАТЕМАТИКА_ВЕТРА.md** в окне программы можно простым текстовым просмотром UTF-8 (без форматирования) либо после реализации Markdown-рендерера. Файл является самостоятельным и не исполняется как расчетный код.
