# Интеграция в Ebala, проверка и оставшиеся ограничения

## Предлагаемый интерфейс данных (не изменение кода)

1. `data/SP20_wind_all_in_one.json` — единый вход чтения данных. Можно для экономии памяти читать четыре раздельных файла и не пользоваться общим JSON.
2. У каждой строки таблицы есть `table_id` и контекстные поля. Не объединять строки в один словарь по `scheme_id`: в В.3а есть альтернативы и углы, в В.4 четыре разных набора схем.
3. У каждого графика есть `figure`, `curve_groups`, `curves`, массив `points` и тип шкалы `x.scale`. Нужно сначала выбрать `curve_id`, затем выполнить интерполяцию только **внутри** соответствующего массива узлов.
4. У В.16 и В.17 формулы хранятся как **строковые выражения документации**. Исполнять их через `eval` нельзя. В Go следует реализовать безопасные известные типы функций и проверять параметры математической области определения.
5. Для В.16/В.17 сохранять признаки `engineering_approximation` и применять раздельное обозначение нормативных исходных точек и приближённых расчётных формул. Не представлять аппроксимацию текстом «формула (В.17) СП».
6. **В.17**: по умолчанию использовать фактическую шероховатость в непрерывном выражении, сохраняя возможность явно выбрать консервативный дискретный режим; **В.14/В.16**: выбор дискретных опорных кривых по прежним правилам. Для В.16 нет универсального `max c`, поскольку разрежение отрицательно.
7. В интерфейсе показывать предупреждения о выходе за границы, но не менять введённые инженером исходные числа молча. Выбор, нормативное происхождение и полученный результат должны быть воспроизводимы при повторном открытии проекта.
8. В DOCX выводить реально использованную формулу и уже рассчитанные значения из ядра. В XLSX исходные данные, нормативные точки и формулы должны пересчитываться средствами Excel, как предписывает `PROJECT.md`.

## Проверено

- Файлы CSV/JSON разбираются стандартной библиотекой.
- 13 наборов таблиц, 189 записей; 5 графиков с прямыми сегментами и 2 аналитические модели.
- Узловые значения В.16 воспроизводятся в точках таблицы В.5.
- Промежуточная проверка В.16: `Re=2e6`, `β=100°` даёт по болгарской формуле `c_p≈-1.548528`; на опорных углах функция совпадает с нормативной таблицей В.5. Сравнение по семи углам × трём Re находится в `verification/V16_bulgarian_7_angles.csv` (приближённые значения СП).
- Формула В.17: `Re=1e6`, `δ=1e-3` даёт `c_x∞=0.84`; при `δ=3e-4` непрерывный режим даёт `≈0.74588`, дискретный консервативный `0.84`. Контрольные значения — `verification/V17_control_points.csv` и `verification/V17_roughness_modes.csv`.
- ZIP проверяется на целостность после создания.

## Не следует выдавать за сделанное

- Полная посрочная независимая ревизия всех 189 значений по оригиналу СП.
- Метрологически строгая оцифровка графиков до заданного допуска.
- Утверждение интерполяции по всем промежуточным `h1/l`, `φ` во всех рисунках.
- Сквозная проверка вычислений в работающем ветровом модуле Ebala; такого самостоятельного действующего модуля PROJECT.md не подтверждает.
- Полная реализация раздела 11, остальных аэродинамических схем приложения В и их сочетаний. Данный пакет — **справочные таблицы и семь оговорённых графиков**.
