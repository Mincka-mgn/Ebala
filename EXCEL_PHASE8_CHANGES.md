# Ebala — этап 8. Динамический каталог снеговых загружений в XLSX

**Основа:** исходники после этапа 7. **Новая версия не присваивается, Go и Windows не компилировались.** Расчётное ядро, Word и интерфейс не менялись.

## Цель

Расчётный Excel должен реагировать на изменение исходных размеров и углов не только числами на старых листах, но и актуальным составом **известных, заранее предусмотренных загружений**. Обычный XLSX без макросов не создаёт новые листы; поэтому ограниченное число нормативных вариантов резервируется на момент экспорта, а их применимость вычисляется формулами Excel.

## Что остаётся открытым

1. **Топология при изменении числа пролётов:** без макросов Excel не может создавать произвольное количество новых листов. Для многопролётных вариантов потребуется конечная резервная ёмкость или иное отдельное согласованное представление вариантов, при этом нельзя создавать ложное впечатление полноты.
2. **Конус, купол и Б.15а:** существующие частичные сектора могут становиться неактивными при изменении геометрии, но новые полярные таблицы при переходе через порог 20° пока не появляются. Предварительное резервирование всех шести секторов на каждую круглую кровлю резко увеличивает размер и время пересчёта.
3. **Сложные сопряжённые фонари:** основные совместные варианты Б.3 сохраняются, но одновременные местные заносы Б.8 для обеих частей и влияние расположения фонарей по длине не воспроизведены полностью. При отсутствии формулы экспорт должен сообщать об этом, не выдавая фиктивный μ.
4. **Парапеты по Б.13(в):** резерв местного загружения Б.13 добавлен, но независимый вариант дополнительного Б.8 для парапета не был заново поверен; сохраняется в списке на отдельную проверку.
5. При изменении **типа покрытия** в Excel не перестраивается модель расчёта. Тип является исходным выбором программы; отдельный файл нужен для другого типа.
6. Полные численные проверки формул, корректности готового OOXML, тесты перерасчёта в Excel и проверка Windows пока **не выполнялись**.
