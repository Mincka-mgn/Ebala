Ebala 0.58 — переработка интерфейса ветровых нагрузок
06.11.2026

Основа: Ebala 0.57 и математический пакет Ebala_Wind_Mathematics_v1_1.
Статус: рабочая промежуточная версия, не полный нормативный охват ветровых воздействий.

РЕАЛИЗОВАНО ПО СОГЛАСОВАННЫМ ЗАМЕЧАНИЯМ
1. При отсутствии заданной местности новым ветровым расчётам автоматически назначается наибольший район VII из таблицы 11.1 СП 20.13330.2016. Тип местности остаётся явно выбираемым.
2. В раздел «Местность» добавлен выбор типа местности А/В/С. Команда «Взять из местности» переносит в ветер ТОЛЬКО район и тип местности; если их нет, открывает раздел «Местность» и возвращает к ветру после настройки. Изменение местности не меняет сохранённые расчёты.
3. Единый переключатель кПа / кгс/м² задаёт единицы текущего ветрового расчёта, результатов и эпюры. Выбранные единицы также отображаются в DOCX и на расчётном листе XLSX. Внутри ядра сохранена СИ (Па).
4. Вместо единственной расчётной отметки строится эпюра нагрузки по высоте h. Результаты вынесены на отдельную вкладку; показываются нормативная и расчётная эпюры, таблица ординат, средняя составляющая и предупреждения. Каждая ордината вычисляется исходным математическим ядром, без интерполяции готовых значений ветрового давления. Сохранённый блок включает все ординаты.
5. Исключён двойной выбор аэродинамического коэффициента: единый список «тип сооружения и поверхность» задаёт поддержанную нормативную схему В.1/В.2 и соответствующую зону. Для отсутствующей схемы доступно явное ручное назначение c (с предупреждением).
6. Добавлены фрагменты нормативных рисунков В.1, В.3 и 11.2 из предоставленного СП 20.13330.2016, показывающие направления ветра и геометрические параметры. Ресурсы входят в комплект программы.
7. k(z) назначается по нормативной таблице 11.2. Пользователь не выбирает метод расчёта. Сопоставление таблицы и формулы 11.4 показало несовпадение промежуточных значений: при z=15 м, местности А таблица даёт 1,125, формула ~1,12934694. Нормативные формулы/таблицы не правились.
8. Из интерфейса удалены ввод частот и выбор динамической ветви. Доступны средняя нагрузка и пульсации по формуле 11.5 без собственных частот.
9. Поля геометрии подписаны как h — высота, d — размер вдоль ветра, b — ширина расчётной поверхности; автоматически ρ=b и χ=h для вертикальной стены. Добавлена подсказка о логарифмическом декременте δ по п. 11.1.8, при этом δ и частоты не требуются для доступного расчёта.
10. Исправлен заголовок отдельного DOCX: «РАСЧЁТ ВЕТРОВЫХ НАГРУЗОК»; для смешанной ведомости — общий заголовок.
11. В независимый XLSX добавлен лист «Ветер Эпюра N» с отдельными формулами для каждой высотной точки (включая z_e, k, ζ, среднюю, пульсационную, нормативную и расчётную нагрузки, выбранные единицы). Нормативные данные берутся из JSON, копии чисел в Go не добавлялись.
12. Сохранена логика именованных блоков проекта, ведомости и двух типов экспорта; остальные действующие модули не переписывались.

ОГРАНИЧЕНИЯ И ВОПРОСЫ ДЛЯ СЛЕДУЮЩИХ ЭТАПОВ
- В интерфейсе поддержаны только доступные зоны аэродинамических схем В.1/В.2 и ручной c. Остальные аэродинамические схемы приложения В не реализованы. Эпюра относится к одной выбранной поверхности/зоне, не является пространственным набором всех одновременных загружений.
- Для отдельных зон по В.1/В.2 распределение коэффициента вдоль поверхности автоматически не меняется; пользователь создаёт самостоятельные варианты для нужных поверхностей.
- Динамический расчёт с учётом резонанса и собственных частот, расчёт по приложению М, пиковые ветровые нагрузки, аэродинамические неустойчивости и специальные сооружения не реализованы в этой очереди.
- Применяемый для ν табличный метод интерполяции может сопровождаться предупреждением об отсутствии прямого нормативного указания метода интерполяции. Математическая спецификация не изменялась.
- Выбранные высотные точки задаются на момент экспорта; в Excel значения ординат пересчитываются из редактируемых исходных данных, но при существенном изменении геометрии набор точек и зон может потребовать повторного экспорта.
- Интерфейсная работа программы на реальном компьютере с Windows и открытие отчётов в Microsoft Office в среде сборки не проверены; требуется пользовательская приёмка.

ВЫПОЛНЕННЫЕ ПРОВЕРКИ
- Go: профиль от 60 точек, совпадение каждого узла профиля с прямым вызовом исходного ядра; проверка границ выбора эквивалентной высоты.
- Отдельно проверены вариант стены с эквивалентной высотой h, коэффициенты В.1/В.2, назначение максимального района VII, выбранные единицы, сохранение/повторное чтение профиля и DOCX/XLSX.
- Сохранена проверка SHA-256 и контроль нормативных данных; математическая документация в полном архиве исходников.
- Структура Word DOCX проверена, просмотрена отрисованная страница. Структура Excel XLSX проверена, формулы связаны с отдельными исходными данными и нормативными листами.
- Регрессионные тесты Go и семь проверочных скриптов математического архива. Windows x64 GUI-кросс-сборка (PE Subsystem 2) и проверка целостности ZIP.

СБОРКА
Команда из корня исходников:
GOOS=windows GOARCH=amd64 GO111MODULE=off go build -ldflags="-H=windowsgui -s -w" -o Ebala_0.58.exe .
Запуск из распакованной рабочей папки: Ebala_0.58.exe. Наличие папок Catalog, Databases, Maps, Resources и WindData обязательно.
