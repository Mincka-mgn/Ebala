# Ebala 0.51 — аудит и перечень исправлений следующей версии

**Дата:** 04.11.2026  
**Исходный код:** `Ebala_0.51_Sources.zip` (исходники 0.51, без изменений).  
**Основа критериев:** действующий `PROJECT.md`, особенно §§ 3, 5.1, 6.1–6.4.  
**Основной предмет:** самостоятельный XLSX-расчёт по принятым исходным данным, согласованность его формул с Go, Excel-структура и отчётный экспорт.  
**Статус:** статическая ревизия Go/OOXML, создание контрольных XLSX в отдельной копии исходников, целевые Go-тесты. Не проводился живой пересчёт в Microsoft Excel и визуальная проверка GUI/Word под Windows.

## Краткое заключение

В версии 0.51 сделана **рабочая основа формульного XLSX**: отдельные листы исходных данных, СП 20.13330.2016 табл. 10.2/11.2, интерполяция k(H), формульные листы коэффициентов, варианты и пространственные сетки Б.15а. Однако **архитектурный инвариант «Excel получает только исходные данные» не выполнен**. Главный расчётный лист продолжает содержать μ, пришедшие из ядра; отдельные формульные листы могут содержать явные ошибки `=NA()`; для высокого купола найдено численное расхождение при исходных, ещё не редактировавшихся параметрах. Отчёт Excel **не готов к независимой проверке заказчиком** во всех схемах.

## 3. Что в 0.51 действительно работает и должно быть сохранено

- Расчётный Go-код и Word намеренно не подвергались непрошеной реорганизации.
- Снеговый XLSX содержит отдельный лист входных параметров и листы **таблиц 10.2 и 11.2 СП 20.13330.2016**; `kv`, высотный `k(H)`, `ce` и `ct` на специализированных листах получают действующие формулы. Табличные значения 10.2 и 11.2 сопоставлены с предоставленным PDF СП, грубых расхождений в наборах узлов не обнаружено.
- Для Б.15а реализованы отдельный формульный лист геометрии, пространственные листы и два режима зоны 5; это реальная основа, а не только имитация формул.
- Нормативные таблицы гололёда 12.2–12.4 вынесены на самостоятельные листы, есть формулы высотного выбора и интерполяции. Полная численная поверка этих зависимостей пока не проводилась.
- В контрольных снеговых XLSX первые ячейки A1 всех листов содержат требуемое «На этом листе…», а первый лист называется «Исходные данные».
- Самостоятельный экспорт собственного веса умеет считать по толщинам и плотностям; недостаточность исходных данных характерна прежде всего для общей ведомости.

## 4. Проверки, воспроизводимые контрольные данные

1. **Анализ исходников 0.51:** чтение `PROJECT.md`, файлов генератора `snow_report.go`, `snow_excel_v031.go`, `snow_excel_sphere_050.go`, `snow_excel_norm_051.go`, `ice_excel.go`, `excel_051_ledger.go`, `temporary_excel.go`, основного снегового ядра. Оригинальные файлы НЕ изменялись.
2. **Существующие образцы релиза:** статический анализ OOXML `sphere_alpha2.xlsx`, `sphere_alpha1_strict.xlsx`, `cone.xlsx`, `dome.xlsx`. Excel-файлы структурно доступны; это **не** подтверждение вычисленных Excel результатов.
3. **Новый контрольный экспорт фонаря:** в отдельной копии исходников созданы `skylight.xlsx` с 6 загружениями и `tall_dome.xlsx`. В `skylight.xlsx` в листах «Вариант 5», «Вариант 6» реально обнаружены ячейки `C5=NA()`, `C6=NA()` при наличии корректного результата в расчётном ядре. Сам экспорт завершился без ошибки.
4. **Математический контроль высокого купола:** ручная геометрия `D=18`, `f=12`, `R=9.375`, при `x=3` вычислены α и μ для двух подходов. Это демонстрация логического расхождения формул, не зависимая от наличия Microsoft Excel.
5. **Целевые тесты:** `GO111MODULE=off go test ./... -run 'Test051|Test050SphereCone' -count=1 -timeout 100s` — PASS. Два дополнительных тестовых экспорта в независимой копии исходников — PASS по запуску; ошибку формул они не ловили, она установлена чтением OOXML.
6. **Полный Go-тестовый прогон:** в `CHANGES_0.51.txt` указан PASS полного комплекта на момент сборки версии 0.51; в рамках настоящего аудита **повторно не запускался**, поэтому не приписываем ему результаты текущей поверки.
7. **Не проверено:** независимый вычислительный движок Excel на каждой формуле, пересчёт в Microsoft Excel после редактирования, визуальная корректность Word, GUI на Windows, все варианты остальных расчётных модулей.

## 5. Очерёдность следующей разработки

**Пакет А, целостность Excel (обязательный перед эксплуатацией):** 51-01 → 51-02 → 51-03. Устранить ложные готовые значения, `#Н/Д` и известное неверное μ. Автоматический тест на каждую ошибку.

**Пакет Б, независимость и воспроизводимость:** 51-04 → 51-06 → 51-07 → 51-08; согласовать с 51-05. Ввести прозрачный контракт «исходные параметры → нормативные таблицы → коэффициенты → загружения → итоги → связанные графики»; исключать из XLSX результаты Go, кроме матричного исключения.

**Пакет В, инженерная пригодность:** 51-09 → 51-10 → 51-11 → 51-12. Проверить нетипичные значения, независимую численную поверку и фактическую работу Excel.

Задачи 51-C1…C4 затем можно выполнять самостоятельно по утверждённому плану; в настоящем аудите они **не исправлялись**.

**Итог:** нельзя принимать версию 0.51 как завершение независимой архитектуры Excel. При этом начинать полностью заново не нужно: листы исходных данных, нормативных таблиц, интерполяции и большая часть раздельных формульных листов уже созданы и являются основой для доведения до требуемого поведения.
